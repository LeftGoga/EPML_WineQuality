# Отчет по проделанной работе: Интеграция Luigi и Hydra

## Выбранные инструменты

Для оркестрации пайплайна выбрал **Luigi**, а для управления конфигурациями - **Hydra**.

---

## 1. Настройка выбранного инструмента оркестрации (4 балла)

### a) Установка и настройка Luigi

Luigi установлен через Poetry и интегрирован в проект через модуль `src/wine_quality/luigi_pipeline.py`.

![alt text](../pics/luigi_install.png)

### b) Создание workflow для ML пайплайна

Создал полный workflow, состоящий из пяти задач:

1. **`PrepareData`** - загружает и сохраняет исходные данные
2. **`GenerateFeatures`** - генерирует признаки и создает целевую переменную
3. **`TrainModel`** - обучает модель с поддержкой конфигураций Hydra
4. **`EvaluateModel`** - оценивает модель и создает отчет
5. **`WineQualityPipeline`** - главная задача, объединяющая все этапы

Каждая задача интегрирована с системой уведомлений, логирует время выполнения и метрики, а также обрабатывает ошибки. Главная задача имеет обработчики `on_success()` и `on_failure()` для финальных уведомлений.

### c) Настройка зависимостей между этапами

Зависимости настроены через метод `requires()`:

```
PrepareData → GenerateFeatures → TrainModel → EvaluateModel → WineQualityPipeline
```

Luigi автоматически определяет порядок выполнения и пропускает задачи, если выходные файлы уже существуют.

### d) Реализация кэширования и параллельного выполнения

**Кэширование** реализовано через механизм `output()` - Luigi проверяет существование выходных файлов и пропускает выполнение, если они актуальны.

![alt text](../pics/luigi_cash.png)

**Параллельное выполнение** настраивается через конфигурацию в `conf/pipeline/pipeline_luigi.yaml`:

```yaml
pipeline:
  parallel: true
  workers: 4
  scheduler: central  # или local
```

Поддерживаются два типа планировщиков: `local` (локальный) и `central` (требует запущенного `luigid`).

## 2. Настройка выбранного инструмента конфигураций (3 балла)

### a) Настройка Hydra для управления конфигурациями

Hydra установлен через Poetry и интегрирован через декоратор `@hydra.main()` в `src/wine_quality/orchestrator.py`. По умолчанию используется `config.yaml`, но можно переключиться на другую конфигурацию:

```bash
python run_luigi_pipeline.py --config-name=config_luigi
```

### b) Создание конфигураций для разных алгоритмов

Создана иерархическая структура конфигураций в `conf/`:

- **Модели** (`conf/model/`): для Random Forest, Boosting и MLP есть базовые, быстрые и глубокие варианты
- **Данные** (`conf/data/`): базовые, строгие и мягкие конфигурации с разными порогами качества
- **Окружение** (`conf/env/`): конфигурации для dev, test и prod
- **Пайплайн** (`conf/pipeline/`): параллельное и последовательное выполнение

### c) Настройка валидации конфигураций

Валидация реализована через Pydantic схемы в `src/wine_quality/config_schema.py`. Схемы проверяют типы, диапазоны значений и обязательные поля. Валидация выполняется при запуске пайплайна.

### d) Создание системы композиции конфигураций

Композиция реализована через механизм `defaults` в Hydra, что позволяет легко переключаться между конфигурациями:

```bash
# Базовая конфигурация
python run_luigi_pipeline.py

# Быстрая конфигурация Random Forest
python run_luigi_pipeline.py model=random_forest_fast

# Глубокая конфигурация Boosting со строгими данными
python run_luigi_pipeline.py model=boosting_deep data=data_strict

# Последовательное выполнение
python run_luigi_pipeline.py pipeline=pipeline_sequential
```

## 3. Интеграция и тестирование (2 балла)

### a) Интеграция выбранных инструментов

Интеграция Luigi и Hydra реализована в `src/wine_quality/orchestrator.py`. Конфигурация Hydra передается в Luigi задачи через параметры `hydra_config_path`, `hydra_config_name` и `hydra_overrides`, что позволяет задачам загружать и использовать те же конфигурации. Параметры моделей из Hydra автоматически преобразуются в параметры Luigi задач.

### b) Создание системы мониторинга выполнения

Реализован класс `PipelineMonitor`, который логирует начало, завершение и ошибки выполнения задач. Логи сохраняются в JSON формате в `outputs/pipeline_logs/` с временными метками в имени файла. Мониторинг можно включить/выключить через конфигурацию.

![alt text](../pics/luigi_graph.png)
![alt text](../pics/luigi_ui.png)

### c) Настройка уведомлений о результатах

Реализован класс `NotificationSystem` с поддержкой email уведомлений. Система:
- Выводит уведомления в консоль
- Отправляет HTML email через SMTP (настраивается через переменные окружения)
- Автоматически определяет тип соединения (SSL/STARTTLS)
- Форматирует email с таблицами и цветовой индикацией

![alt text](../pics/email_not.png)

### d) Тестирование воспроизводимости

Воспроизводимость обеспечивается через:
1. Фиксацию `random_state: 42` в конфигурации
2. Версионирование зависимостей через Poetry
3. Логирование всех параметров в MLflow и локальные файлы
4. Кэширование результатов через Luigi

При повторном запуске с теми же параметрами задачи не перевыполняются. Результаты сохраняются в:
- `models/wine_<model_type>.pkl` - обученная модель
- `models/wine_<model_type>_metrics.json` - метрики
- `models/wine_<model_type>_report.json` - отчет
- `outputs/pipeline_logs/` - логи выполнения

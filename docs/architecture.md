# Архитектура проекта

Обзор архитектуры проекта Wine Quality ML.

## Общая структура

Проект следует модульной архитектуре с четким разделением ответственности:

```
wine_quality_epml/
├── src/wine_quality/        # Основной код
│   ├── data.py              # Загрузка данных
│   ├── features.py          # Инженерия признаков
│   ├── model.py             # Модели ML
│   ├── config.py            # Конфигурация
│   ├── clearml_*.py         # ClearML интеграция
│   └── ...
├── conf/                     # Конфигурационные файлы
├── data/                     # Данные
├── models/                    # Сохраненные модели
├── docs/                     # Документация
└── hw_reports/               # Отчеты
```

## Компоненты

### 1. Слой данных (Data Layer)

**Модуль:** `data.py`

Ответственность:
- Загрузка данных из различных источников
- Предобработка данных
- Разделение на train/test

**Основные функции:**
- `load_data()` - загрузка данных
- `create_target()` - создание целевой переменной
- `split_data()` - разделение данных

### 2. Слой признаков (Features Layer)

**Модуль:** `features.py`

Ответственность:
- Инженерия признаков
- Создание производных признаков
- Трансформация данных

**Основные функции:**
- `engineer_features()` - создание новых признаков

### 3. Слой моделей (Model Layer)

**Модуль:** `model.py`

Ответственность:
- Обучение моделей
- Оценка моделей
- Сохранение моделей

**Поддерживаемые модели:**
- Random Forest
- Gradient Boosting
- MLP (Neural Network)

### 4. Слой трекинга (Tracking Layer)

**Модули:** `clearml_*.py`, `mlflow_*.py`

Ответственность:
- Логирование экспериментов
- Версионирование моделей
- Сравнение экспериментов

**Интеграции:**
- ClearML
- MLflow (опционально)

### 5. Слой пайплайнов (Pipeline Layer)

**Модуль:** `clearml_pipeline.py`, `luigi_pipeline.py`

Ответственность:
- Оркестрация workflow
- Автоматизация процессов
- Управление зависимостями

## Поток данных

```
1. Загрузка данных
   ↓
2. Создание целевой переменной
   ↓
3. Инженерия признаков
   ↓
4. Разделение на train/test
   ↓
5. Обучение модели
   ↓
6. Оценка модели
   ↓
7. Логирование в ClearML
   ↓
8. Регистрация модели
```

## Конфигурация

Проект использует несколько уровней конфигурации:

1. **Константы** (`config.py`) - базовые настройки
2. **YAML конфигурации** (`conf/`) - детальные настройки
3. **Hydra** - управление конфигурациями
4. **Переменные окружения** (`.env`) - секреты и переменные

## Интеграции

### ClearML

- Трекинг экспериментов
- Версионирование моделей
- Пайплайны
- Дашборды

### MLflow (опционально)

- Альтернативный трекинг
- Регистрация моделей

### Luigi

- Оркестрация задач
- Управление зависимостями

## Масштабируемость

Проект спроектирован для масштабирования:

- **Горизонтальное**: Запуск нескольких экспериментов параллельно
- **Вертикальное**: Использование более мощных моделей
- **Распределенное**: ClearML агенты для распределенной обработки

## Безопасность

- Секреты хранятся в переменных окружения
- Конфигурации не содержат чувствительных данных
- Проверка безопасности кода через bandit

## Тестирование

- Модульная структура облегчает тестирование
- Каждый компонент может быть протестирован независимо

## Расширяемость

Проект легко расширяется:

- Добавление новых моделей через `ModelType` enum
- Добавление новых признаков в `features.py`
- Добавление новых источников данных в `data.py`
